\# Release Policy (Kernel Next)



This document defines how releases are created during the kernel-next phase.



Releases are used to mark \*\*clarity milestones\*\*, not feature delivery.



---



\## Versioning Rules



\- Versions follow `v0.x.y`

\- Increments represent documentation maturity

\- No semantic promises are implied



---



\## When to Tag



A tag may be created only when:

\- Documentation is internally consistent

\- No partial drafts remain

\- The repository is review-ready



---



\## What a Release Means



A release signals:

\- Stability of intent

\- Locked governance posture

\- Safe external reference point



It does \*\*not\*\* signal:

\- Readiness for implementation

\- Availability of runtime systems



---



\## Immutability



Once published:

\- Tags are never moved

\- History is never rewritten
